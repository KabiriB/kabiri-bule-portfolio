04 / Approach and interpretation

What this demonstrates—and what it does not.

  1. Corpus preparation. Twenty-seven independently authored summary passages are assigned source, topic, identifier and official URL. This deliberately small testbed makes the behaviour inspectable.
  2. Indexing and retrieval. The browser tokenises the question, removes generic words, applies transparent synonym expansion and ranks passages using a length-normalised term relevance formula. The algorithm and corpus are publicly inspectable.
  3. Evidence presentation. The interface surfaces the highest-ranked supporting passages, labelled as paraphrases, with links back to primary sources. It does not write a novel answer beyond those passages.
  4. Abstention. If retrieval is weak or the subject is outside the corpus, the interface says it lacks sufficient evidence rather than fabricating a source. This is a heuristic, not a perfect guardrail.
  5. Evaluation. A fixed test set checks whether expected evidence appears in the top three retrieved passages and whether unsupported questions are refused. The corpus and tests are small, so performance is a demonstration, not a production benchmark.

Evidence and deployment boundary: This is a functional retrieval-and-citation prototype of the evidence layer used in retrieval-augmented generation systems. It does not run an LLM, reason semantically over full documents, ingest private files, deliver authoritative legal advice, or operate as a production AI service. Further work would include document ingestion, permission-aware retrieval, semantic embeddings, actual grounded generation and human-rated answer evaluation.
